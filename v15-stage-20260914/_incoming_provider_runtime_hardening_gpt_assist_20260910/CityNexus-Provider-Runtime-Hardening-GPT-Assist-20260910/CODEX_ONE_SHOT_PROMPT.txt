==================================================
B. 5 个必须收口的问题
==================================================

PRH-01 MobilitySnapshot 只是 frozen dataclass，但 facts 还是 mutable dict。

当前能做：

    snapshot.facts[("a", "b")] = ...

这会破坏 same-operation frozen reality。

最小参考方案：MobilitySnapshot.__post_init__ defensive copy + MappingProxyType，并校验 mapping key 与 fact origin/destination 一致。

--------------------------------------------------
PRH-02 JourneyTwin partial fallback provenance 错。

例：

    snapshot source provider = valhalla
    TechArt -> RiverCruise 这个具体 fact = mock-mobility fallback

Twin 当前却报告 provider=valhalla。

Twin 应至少区分：

    provider        = 实际用于这个 C4 buffer 的 fact.provider_key
    source_provider = snapshot.source_provider_key
    snapshot_id
    degraded
    snapshot_degraded
    fallback_reason

不要把 primary provider 和 effective fact provider 混成一个字段。

--------------------------------------------------
PRH-03 degraded mobility 没进入 FeasibilityEnvelope / robustness scoring。

目前可能同时出现：

    verified_evidence.mobility.degraded = true
    after_feasibility_envelope.degraded_providers = []
    robust = true
    score_breakdown.robustness = 1.0

这是内部事实矛盾。

把当前 snapshot 的 degraded provider 明确传入 before/after FeasibilityEnvelope，让 PROVIDER_DEGRADED 风险进入 verified robustness score。

--------------------------------------------------
PRH-04 travel_delta_min 在比较两个不同的 reality。

Candidate 的 travel_from_prev 已由新 frozen snapshot 重算，
但 base route total 仍使用旧 persisted travel_from_prev_min，通常来自 mock planning。

GPT 用 constant 1-minute provider 证明：

    current diff = -85
    same-snapshot expected diff = 0

因此当前 score 可能奖励“provider 从 mock 换成 Valhalla”，而不是奖励真正更好的 Replan。

必须：

    base route total
    candidate route total

都用同一 frozen MobilitySnapshot 计算，再得到 travel_delta_min。

--------------------------------------------------
PRH-05 Accept Replan 又偷偷回到了默认 MockMobilityProvider。

Generation：

    frozen MobilitySnapshot -> validate_plan_feasibility

Accept：

    validate_plan_feasibility(...)
    -> implicit MockMobilityProvider

这会让 proposal 在 Valhalla reality 下生成，却在 mock reality 下最终接受/拒绝。

本轮最小安全方案：

    ReplanProposal.diff_json
    -> reconstruct persisted MobilitySnapshot
    -> accept-time validate_plan_feasibility(... mobility_provider=snapshot)

如果你认为应该在 Accept 时 capture fresh mobility，这是允许的更高级方案，但必须：
- provider call 在 Gate 外；
- 产生一个新的 frozen acceptance snapshot；
- 持久化 provenance；
- 明确 freshness policy；
- 绝不能 silently fallback 到 unrelated default Mock。

当前课程 milestone 为减少变量，优先复用 proposal snapshot。
