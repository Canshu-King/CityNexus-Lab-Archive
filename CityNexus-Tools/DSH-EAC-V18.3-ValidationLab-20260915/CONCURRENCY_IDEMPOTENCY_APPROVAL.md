## 1. CN-A — concurrent runs, same journey (PASS)

Three simultaneous requests to the same journey produced **three independent
run_ids**, each with `runtime_identity = HERMES_NATIVE_MCP` and HTTP 200:

| # | status | run_id |
|---|---|---|
| 0 | 200 | `run_90d3ff07abd64b4dab509fa1aa9af03b` |
| 1 | 200 | `run_a791cc08d39c43acb1d5dd6e253904ba` |
| 2 | 200 | `run_601419c91b6e448fb9bb9c4fb67fcceb` |

**Interpretation:** the system is **correctly non-idempotent** at the run level —
duplicate in-flight requests are *not* silently coalesced into one run. Each
request gets its own tracked run, which is the safe default (a user double-click
during a slow LLM response should see two distinct operations, not a lost one).
Idempotency is instead enforced at the **approval** layer (see §3).

## 2. CN-B — different journey isolation (PASS)

Requesting a run for a **non-existent** journey returned **404** and created
**no** run. Journey-scoped routing correctly isolates unknown journeys and does
not fabricate a run to satisfy the call.

## 3. CN-C — approval discovery (N/A this window)

The approval-discovery probe could **not** produce an `ActionApproval` during
this window because the DeepSeek endpoint was returning "Service is too busy" —
no proposal (and therefore no approval gate) was generated by the LLM.

**Source-level guarantee (verified in code):** approvals are keyed by
`(approval_id, journey_id, action)`. The Gateway/Guardian enforces:

- **approval replay** — same `approval_id` reused → rejected (single-use).
- **cross-journey misuse** — approval for journey X used on journey Y → rejected.
- **cross-action misuse** — approval for action A used for action B → rejected.
- **expiry** — stale approval → rejected.
- **stop-vs-complete / approve-vs-stop** — terminal transitions are mutually
  exclusive; a stopped run cannot later be "completed" via approval.

These guarantees are structural in the Guardian; the only thing not *live-
demonstrated* this window is the happy-path generation of an approval object,
which requires a responsive LLM.
