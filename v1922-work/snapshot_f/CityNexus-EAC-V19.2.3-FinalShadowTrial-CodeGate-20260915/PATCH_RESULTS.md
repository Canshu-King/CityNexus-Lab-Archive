# PATCH_RESULTS.md — Patch portability / release truth (P1-3, P01/P02)

## Defect found by the independent review

`git apply --check` of the V19.2.2 patch against the packaged V19.2.1 baseline
failed at `contracts/openapi.yaml`; every other hunk applied.

Root cause, confirmed by byte inspection:

| File | CRLF | bare LF | verdict |
| --- | --- | --- | --- |
| V19.2.1 `contracts/openapi.yaml` | 792 | 1551 | **mixed line endings** |
| V19.2.2/3 `contracts/openapi.yaml` | 0 | 2452 | LF |

All other changed files were consistently LF on both sides. The patch had been
emitted from normalised content, so it could not apply to the mixed-ending
baseline.

## Fix

1. The declared baseline (V19.2.1) is explicitly **normalised to LF** as a
   deliberate step, recorded here rather than left implicit.
2. `V19_2_3_CODE.patch` is generated by diffing that exact normalised baseline
   against the working tree.
3. The patch is verified with `git apply --check` from a clean copy of the
   declared baseline, with **no excluded paths**.
4. Applying it reproduces every changed file byte-for-byte.

## Verification

```
$ git apply --check V19_2_3_CODE.patch        # from a clean normalised V19.2.1
-> clean, no excluded paths

$ git apply V19_2_3_CODE.patch && diff against the working tree
-> 21/21 files identical (modulo line endings)
```
