# DESIGN_CORRECTIONS_REQUIRED

这份文件优先级高于图片中文字中的偶发矛盾。

## 1. 正式主导航

所有新 UI 正式统一为：

- 今天
- 行程
- 地图
- Copilot
- 我的

**钱包不能继续占主导航黄金位置。**

钱包 / 订单 / 凭证应进入：

- 行程 -> 预订与凭证
或
- 我的 -> 钱包

## 2. Demo 数据统一

今晚所有浏览器流程统一使用一套测试事实，避免页面互相打架。

推荐：

- 目的地：厦门
- 抵达：厦门高崎国际机场
- 离开：厦门北站
- 2 位旅行者
- 总预算：CNY 3000
- 住宿预算：CNY 1000

日期可以为了真实 provider 测试缩短，但前后必须一致。

不要同时出现：
- 首页 ¥8000
- 创建页 ¥3000
- 方案页又 ¥10000

若 AI 方案超过预算，必须明确：
- 超预算多少
- 为什么
- 怎么降低

绝不能装作预算约束不存在。

## 3. 抵达/离开语义

创建页面不要使用容易误解的“出发地/到达地”。

对目的地旅行使用：

- 抵达厦门：厦门高崎国际机场
- 离开厦门：厦门北站

这与 C4 ARRIVAL / DEPARTURE 语义一致。

## 4. 创建行程最终流程

必须真正存在三步：

1. 目的地与时间
2. 人数 / 预算 / 偏好
3. 确认创建

当前 10 张参考图只画出了 Step 1 和 Step 2。

EAC 必须实现 Step 3，而不是删掉第三步。

Step 3 最少显示：

- 目的地
- 抵达 / 离开时间地点
- 人数
- 总预算 / 住宿预算
- 节奏 / 兴趣
- 特殊要求
- 返回修改
- 确认创建

## 5. 国家 / 时区 / 货币

普通用户不应该在主流程被迫理解：

- CN
- Asia/Shanghai
- CNY

选中“厦门”后应自动推断。

主界面最多显示：

“已自动设置：中国 · 人民币 · 中国标准时间”

详细字段放“高级设置”。

## 6. AI 进度

图片里的“72%”只是视觉参考。

如果后端没有真实数值进度：
- 不允许伪造百分比
- 使用真实阶段 stepper + indeterminate progress

例如：

✓ 理解需求
✓ 搜索真实地点
● 检查时间与交通
○ 生成可选方案

## 7. 方案比较与预算

用户预算 3000 时，不能默默提供三个 4500/8000/10000 的方案。

正确表现：

- 预算内
- 接近预算上限
- 超预算 +1200

并提供：
- 为什么超
- 哪些活动/住宿可以降低费用

## 8. 多日行程

39 天只是压力测试，不代表 UI 应该横向滑 39 个 Day chips。

长行程必须使用：
- 周分组
- 日期选择器 / 日历
- 周视图 + 日详情

短行程可以更简单。

## 9. Copilot action

永远禁止普通用户看到：

- REQUEST_PLACE_SEARCH
- PlanVersion
- C4
- semantic_key
- deterministic gate
- provider evidence
- raw enum

内部 action 必须转换成人话并尽可能真实执行。

## 10. Map truth

厦门 Journey 永远不能因为缺数据自动显示天津。

坐标优先级：

1. 当前真实位置
2. 当前/选中活动坐标
3. 抵达/离开地点坐标
4. 已解析城市中心
5. 明确空状态

没有可信坐标：
“尚未获取地图位置”
而不是造一个城市。

## 11. Live / Recovery

用户只看：

- 发生了什么
- 哪些受影响
- 哪些不变
- 推荐怎么改
- 接受 / 仅调整今天 / 稍后提醒

底层 Event / ReplanProposal / HARD / C4 都必须保留，但不直接丢给普通用户。

## 12. 会员 / 商业化

当前不是会员营销项目。

不要在核心旅行流程中加入大面积会员升级卡。
先把产品做能用。
