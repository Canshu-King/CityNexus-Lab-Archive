1. PHYSICAL VENUE IDENTITY (the real defect behind the false "recovered")
------------------------------------------------------------------
FILE: backend/app/replanning/mock_replan_engine.py
WHY:  A closed venue must never be offered as its own replacement.
      One physical venue can exist as two Place rows:
        * a domain wrapper (provider citynexus-v9-domain,
          external_id "CN-XIAMEN:real-place-<hex>")
        * the provider row it wraps (provider overpass)
      They have different ids but identical coordinates and cross-referencing
      identifiers. Excluding candidates by id alone let a replan "replace" a
      closed restaurant with that same restaurant under a new id: the plan
      looked recovered, the diff was minimal, and the traveller was still
      sent to a closed venue.
ADDED:
  - _coordinates(place)
  - _identity_tokens(place)         tokenises id + external_id (>=8 chars, has a digit)
  - is_same_physical_venue(left, right)
      true when: same id, OR identical rounded coordinates, OR shared identity token
  - rank_closure_replacements(..., occupied_places=None)
      new optional argument; candidates are now also excluded when they are
      physically the same venue as an already-used stop.
CHANGED:
  - the exclusion loop now uses is_same_physical_venue instead of id equality.

FILE: backend/app/main.py
WHY:  both replan call sites must supply the rows, not just the ids, so the
      physical check can run.
CHANGED:
  - generate_replan(): passes occupied_places=[...] to rank_closure_replacements
    (closure/weather candidate family, ~line 6731)
  - the per-slot candidate loop builds occupied_places once (~line 6874) and
    passes it to every rank_closure_replacements call (~line 6898)

2. HARNESS FALSE POSITIVE (same family as the R1-a "None in {None}" bug)
------------------------------------------------------------------
FILE: D:/moodle/_v1922_work/run_final_v2.cjs   (evidence harness, not shipped product)
WHY:  the closed-place assertion was
        postActs.some((a) => (a.place_id ?? null) === targetPlace)
      but the /experience payload has NO top-level place_id -- it exposes
      identity through metadata.semantic_key. So targetPlace was always null
      and the assertion degenerated to "does any activity have a null
      place_id", which is trivially true. It reported
      closedPlaceReappeared=true on every run, including correct ones, and
      simultaneously hid the real defect in item 1.
CHANGED:
  - compares metadata.semantic_key via semOf(a) instead of place_id
  - records closed_place_reappeared_checked_via = "metadata.semantic_key"
  - removed a dangling closedPlaceStillPresent reference in the log line
